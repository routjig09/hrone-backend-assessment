# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period integer division drops seconds; 10:01 after start is incorrectly counted as 0 minutes late instead of 10. Also ignores timezone and overnight shift date boundaries. | Shift start 09:30, punch-in at 09:40:01. `(punch_in - start).total_seconds() / 60` = 10.0167 min -> `int(10.0167)` is 10. Condition `minutes > 10` evaluates False, returning 0 instead of required 10 (R2). | Measured elapsed seconds against shift start in IST. If `elapsed_seconds > 600`, return `int(elapsed_seconds // 60)`, else return 0. Handle overnight shift start on proper date. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) on binary floating point numbers instead of the required decimal half-up rounding (R4). | Duration resulting in 2.675 hours: Python `round(2.675, 2)` produces `2.67` instead of `2.68`. | Used Python `decimal.Decimal` with `ROUND_HALF_UP` quantization to `0.01` to guarantee exact half-up rounding. |
| 3 | `compute_overtime` (lines 44-47) | Returns overtime for any positive elapsed minutes without enforcing the 30-minute threshold (R3). Also anchors shift end on `date_str` without handling overnight shifts ending on the next day. | Punch-out 18:35 for 18:30 shift end (5 min elapsed): starter returns 5 instead of 0. For overnight shift (22:00-06:00) punched out at 06:40 next morning, end is set to 06:00 on day 1 instead of day 2, returning negative/erroneous value. | Enforced elapsed duration threshold >= 30 minutes; otherwise return 0. Advanced overnight shift end date by +1 day when `shift_end <= shift_start`. |
| 4 | `GET /health` (lines 72-74) | Returns HTTP 200 `{"status": "ok"}` unconditionally without verifying database connectivity. | MongoDB daemon down or invalid `MONGO_URI`: `/health` returns 200 OK instead of HTTP 503. | Added `client.admin.command('ping')` inside a try-catch block; returns HTTP 503 with error detail on connection failure. |
| 5 | `POST /employees` (lines 79-85) | Concurrency race condition: uses preflight check `find_one()` followed by `insert_one()`. Concurrent requests with the same `emp_code` can both pass the check and create duplicate records. | Firing concurrent requests with identical `emp_code` results in duplicate documents or unhandled internal 500 error. | Created unique index on `employees.emp_code` at startup and caught PyMongo `DuplicateKeyError` to return HTTP 409. |
| 6 | `POST /employees` (lines 53-61, 77-85) | Missing input validation for equal shift times (`shift_start == shift_end`), invalid time strings, invalid email regex, and uses local naive `datetime.now()` for `created_at`. | Sending `shift_start: "09:00"` and `shift_end: "09:00"` succeeded with 201 instead of 422. Stored `created_at` lacked UTC timezone and returned naive datetime. | Added Pydantic field validators ensuring `shift_start != shift_end`, email pattern regex matching OpenAPI, and server-generated UTC instant serialized as epoch ms. |
| 7 | `GET /employees` (lines 88-96) | Off-by-one pagination error: `skip = page * page_size` skips the first page completely (for `page=1`, it skips 20 records). Also `total` counts the unfiltered collection instead of the filtered result. | Query `GET /employees?page=1&page_size=20`: returns items 21-40. `GET /employees?department=Engineering`: `total` shows company headcount instead of department count. | Fixed pagination offset to `skip = (page - 1) * page_size`. Set `total = db.employees.count_documents(q)`. Added explicit sort `[("emp_code", 1)]`. |
| 8 | `POST /attendance/punch-in` (lines 101-102) | Unsafe dereference of missing employee: `emp = db.employees.find_one(...)` without checking for None before accessing `emp["shift_start"]`, throwing `TypeError` and 500 error. | Request punch-in for nonexistent employee `EMP9999`: API raises unhandled 500 instead of HTTP 404. | Validated employee existence; raised HTTP 404 when `emp is None`. |
| 9 | `POST /attendance/punch-in` (lines 102-105) | Truthiness bug on `punched_at`: `if body.punched_at:` treats timestamp `0` as falsy. Fails to truncate instants to whole seconds (R1). Uses local system time instead of UTC/IST. | Sending `punched_at: 0` falls back to `datetime.now()`. Milliseconds precision like `.900` are stored instead of truncated whole seconds. | Truncated epoch ms to whole seconds `(ts // 1000) * 1000`, validated timestamp range `100000000000 <= ts <= 4102444800000` via Pydantic, and converted to UTC datetime. |
| 10 | `POST /attendance/punch-in` (lines 103-105) | Attendance date derivation ignores overnight shifts. A punch-in before overnight shift end belongs to previous day's shift (R1). | Overnight shift (22:00-06:00), punch-in at 00:30 on 2026-07-07: assigned date `2026-07-07` instead of `2026-07-06`. | Implemented `derive_attendance_date` checking `shift_end <= shift_start` and comparing punch time against `shift_end` in IST. |
| 11 | `POST /attendance/punch-in` (lines 104-106, 119-120) | Race condition on duplicate punch-in. Also exposes internal MongoDB `_id` as `doc["id"]`, and returns datetime objects instead of epoch ms integers. | Concurrent punch-ins for same employee/date both attempt insert without unique index. Response body includes illegal `"id": "60a..."` and ISO date strings. | Added unique compound index on `("emp_code", "date")`, caught `DuplicateKeyError` to return 409, stripped `_id`, and serialized BSON dates to integer epoch ms. |
| 12 | `GET /attendance` (lines 136-142) | Dictionary overwrite bug on date filter: `q["date"]` gets overwritten if both `date_from` and `date_to` are present. | Filter `?date_from=2026-07-01&date_to=2026-07-10`: only `$lte` remained in `q["date"]`, losing `$gte`. | Formatted date query as `{"date": {"$gte": date_from, "$lte": date_to}}` properly combining both bounds. |
| 13 | `GET /attendance` (lines 144-150) | In-memory materialization and sorting: loads the entire attendance collection into Python with `list(find(q))`. Fails determinism on sort and leaks `_id`. | On large datasets (e.g. 100,000 records), high latency and memory spikes. Missing secondary sort causes unstable pagination order. | Pushed pagination, date filtering, and compound sorting `[("date", -1), ("emp_code", 1)]` directly into MongoDB query cursor. Excluded `_id`. |
| 14 | `GET /attendance` (lines 125-132) | Missing date range validation: does not check if `date_from > date_to`, which requires HTTP 422 under the OpenAPI contract. | Query `?date_from=2026-07-10&date_to=2026-07-01`: returned 200 with empty list instead of HTTP 422 validation error. | Added query parameter validation raising HTTP 422 when `date_from > date_to`. |
| 15 | `GET /attendance` (lines 148-150) | Missing schema normalization for legacy documents: documents missing `history` or `half_day` return incomplete payloads. | Querying legacy documents seeded without `half_day` or `history`: response omits these required fields. | Defaulted missing legacy fields (`half_day: False`, `history: []`, `late_minutes: 0`, `overtime_minutes: 0`, `work_hours: None`). |

### What was examined and found correct:

1. **IST Offset Definition (`timezone(timedelta(hours=5, minutes=30))`):**
   - The offset of +05:30 matches Indian Standard Time (IST) exactly and has no daylight savings shifts. This was retained.
2. **Path parameter naming and route structure:**
   - Routes `/health`, `/employees`, `/attendance/punch-in`, `/attendance` match the OpenAPI spec paths.
3. **Environment variable names:**
   - Reading `MONGO_URI` and `MONGO_DB` with fallback defaults aligns with the candidate kit configuration contract.
